❓ Cooper Control Panel — Help

This panel controls Cooper, the One Comcentre AgiBot X2 Ultra ambassador robot. All buttons talk directly to Cooper over the network.

Server status bar (top of the screen)

Shows whether the control API (the small program that relays panel commands to the robot) is reachable at the address in Settings. Green = online and ready; red = unreachable — all controls, including the Microphone/Speaker radios, are disabled and show "unknown" until the connection comes back. When red: press 🔄 Restart server (an on-demand install starts within a couple of seconds; the panel also retries every 3 seconds by itself), and double-check the address in ⚙ Settings — a typo there is the most common cause. While a panel is open, an on-demand API never stops itself; its idle timer only runs when no panel is connected anywhere. Next to Help, a 🔋 battery chip shows Cooper's live charge (⚡ while charging; amber under 30%, red under 15%) — it appears once the robot's battery topic is detected and updates every few seconds. At the far right, the small version tag (e.g. v2026.09.12-1) identifies this page's build; if it turns amber showing "page ≠ API", the webpage on optimus and the server on Cooper are on different versions — re-copy the page or update/restart the API so they match.

⚙ Settings — Connection

  • Cooper IP address / port — the robot runs the control API (cooper_panel_server.py); this page is only hosted on optimus. In the show suite the address is 192.168.68.54 port 8080 (the default); at an event, type Cooper's IP on that network. The value is remembered, and an invalid saved address is discarded automatically.
  • Panel PIN — required for every control action (listening, dance, show, shortlist changes). Enter it once per device; it is remembered. Without the PIN the panel can only view status.
  • Connect — saves the settings and tests the connection. Normally not needed: the panel connects by itself when opened.
  • Active robot / Secondary robot IP — a backup X2 can take over the performance if the main robot fails. Enter the backup robot's IP address once; then switch robots with the Active robot selector, or — when the status bar is red — press 🤖 Use backup robot right on the bar to continue the show on the other robot. Each robot keeps its own shortlist, play times, and song alerts (they live on the robot itself).

Audio — microphone and speaker

🎙 Microphone On / Off — Off means Cooper ignores surrounding conversation and will not answer the audience. During a show the script controls the microphone itself: muted at the start, and it stays muted afterwards unless "listen again after show" is ticked.
🔊 Speaker On / Muted — Muted sets Cooper's volume to zero, so no speech or sound comes out (useful for a silent rehearsal); On restores the normal volume.
🔉 Volume slider — sets the speaker level directly (0–100); sliding to 0 is the same as Muted, and the last non-zero level you set is what "Speaker On" restores. Speaker and volume stay usable even while a show is running.

Actions

Pick a gesture from the dropdown and press ▶ Execute — Cooper performs it immediately. Built in: 🤝 Shake hand, 🫶 Heart sign (both hands), 👋 Right-hand goodbye, 🖐️ Left-hand wave, and 😘 Blow kiss, plus two ⭐ custom entries (out of the box: Right-hand wave and Both-hands heart) whose label and motion/area ids are editable in ⚙ Settings → "Custom actions" — changes apply to every device. Gestures move the robot only — no speech, and the microphone is not affected. Execute is disabled while a full show is running so gestures cannot interrupt the performance.

Performance

  • ▶ Run full show — the complete sequence: wave + welcome, introduction, dance, bow, clap, thank-you + heart, goodbye + blow kiss, goodbye wave. Buttons lock while a show is running.
  • Show dance — the song the show (and Play dance only) uses is chosen once in ⚙ Settings → "Show dance" and shared by all devices; the line under the buttons shows the current choice.
  • Play dance only — just the configured dance, nothing else. Does not touch the microphone.
  • listen again after show — tick to have Cooper resume listening when the show ends.

Personalize messages

  • Message group — a group is a complete set of the messages below, and you can keep one per occasion: "Show suite" and "Event" exist from the start, and ＋ New creates your own (it copies the current texts as a starting point; ✏️ renames, 🗑 deletes). Pick a group in the dropdown and the show speaks that group's messages — switch "Show suite" ↔ "Event" with one selection, no retyping.
  • Tenant company / guest name — write {name} anywhere in a message and Cooper speaks this name there. Blank = "everyone".
  • Welcome (morning / afternoon) — two versions of the welcome; Cooper picks by its own clock at show time (morning before 12:00). Fill only one to use it all day.
  • Introduction — spoken after the welcome, before the dance. Note: the "2 meters distance" safety line lives here.
  • Goodbye — spoken near the end, with the blow kiss.
  • Every field is spoken exactly as written; blank fields fall back to the built-in lines. Reset to default messages restores all.

Dance song shortlist (in ⚙ Settings)

Tick the songs that should appear in the main dance list; untick to hide. Nothing ticked = every song is shown. The shortlist is stored on Cooper, so all devices share the same list (changing it needs the PIN). When the AgiBot LinkCraft cloud pushes new songs, a "✨ new dance songs" banner appears — press Review, tick the ones you want, then Mark NEW as seen to clear the alert everywhere. The seconds box next to each song sets how long the full show waits while that dance plays: blank = the default 30 seconds, a number = that many seconds, and 0 = don't wait at all (the show moves straight on). Play times are shared by all devices, like the shortlist.

Performance diagnostics (in ⚙ Settings)

For checking how fast Cooper responds. When on, each button press logs the time split into network (Wi-Fi), server (processing on Cooper), and robot (Cooper's controller accepting the command), with a flow diagram and a live show timeline (launch → first speech → dance → goodbye → complete, measured from your click). Green is fast, amber is slow, red needs attention. Leave off for daily use.

Show-day checklist

  • 1. Power Cooper on and wait for it to finish booting.
  • 2. Open this panel — the server status bar goes green by itself. Red bar? Press 🔄 Restart server; if it stays red, check Cooper's power and Wi-Fi.
  • 3. Enter the PIN in ⚙ Settings (once per device), tick the dance shortlist, and set the tenant name and messages.
  • 4. A "✨ new dance songs" banner means LinkCraft pushed new songs — press Review, tick the ones to use, then Mark NEW as seen.
  • 5. Press ▶ Run full show. Done!

Taking Cooper to an outside event (portable setup)

  • 1. Take a copy of cooper_control_panel.html on the notebook or tablet and open it straight from a folder in the browser — no webserver is needed at the event.
  • 2. Connect Cooper and the notebook to the event network, and note Cooper's IP address on that network.
  • 3. In ⚙ Settings type Cooper's event IP and press Connect. Back at the show suite, change it back to 192.168.68.54.
  • 4. Follow the show-day checklist above. Tip: for events, install Cooper's control API with no idle timer (--idle-exit 0) so it never stops while waiting for the performance slot.

If something is not working

  • Red server bar — Cooper off, wrong setup selected, or network issue. Check ⚙ Settings first.
  • "PIN required" / "invalid PIN" — enter the correct PIN in ⚙ Settings.
  • Dance list empty — press ↻; if still empty, Cooper's dance services may still be starting up.
  • Robot reacts slowly — turn on Performance diagnostics and see which part (network / server / robot) is taking the time.
